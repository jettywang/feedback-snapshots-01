Harden RFC 8308 EXT_INFO handling so an out-of-window, re-key, late, or duplicate/conflicting packet can no longer change the publickey signature capabilities already adopted. The capability-bearing EXT_INFO is accepted exactly once, in the window after the initial NEWKEYS and before authentication begins; malformed framing (bad extension count, truncated name/value strings, trailing bytes) or a repeated extension name disconnect before any authentication signature is produced. Unknown extensions are still retained without being interpreted, and servers that do not send EXT_INFO keep the previous compatibility behavior [#1086]
