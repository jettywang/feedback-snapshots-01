# HTTP 取证关联分析器（基于 h11，只读）

对一条连接的双向字节流做只读分析，还原真实的 HTTP 请求—响应对，
保留两方向的原始偏移与每步解析依据。

## 输入格式

JSON 文件：

```json
{
  "capture_id": "case-001",
  "eof": {"c2s": false, "s2c": true},
  "segments": [
    {"dir": "c2s", "ts": 1.0, "offset": 0, "data_hex": "47455420..."}
  ]
}
```

- `dir`：`c2s`（客户端→服务器）或 `s2c`。
- `offset`：该段在**本方向原始字节流**中的偏移（用于缺失检测）。
- `ts`：捕获时间戳，段按时间顺序处理。
- `eof`：该方向是否观察到连接正常关闭（用于关闭定界正文的完整性判定）。

## 运行

```sh
python3 forensics/make_capture.py                 # 生成合成记录
python3 forensics/analyzer.py <capture.json>      # 文本报告 + <capture.json>.report.json
```

## 判定原则

- 每方向一个 h11 状态机，互为对端同步（代理用法）；偏移由接收缓冲区消耗量精确计算。
- HEAD、多条 1xx、流水化（PAUSED 后 `start_next_cycle`）、关闭定界、
  101 协议切换均按 h11 语义处理；切换后字节只标为“后续协议材料”。
- 偏移缺口、截断、协议错误、初始状态不明 → 明确停止可靠关联，
  绝不搜索 "HTTP" 字样重新认定边界。
- 正文不全量入报告：只记录偏移范围、长度、SHA-256、前 32 字节预览。

## 报告分类

- **已证明的请求—响应对**：请求与响应均完整解析，含双向偏移与定界依据。
- **尚待补齐的范围**：消息未完整，或字节已在捕获中但因前序缺失无法解析。
- **协议切换后的后续协议材料**：101 之后两方向的字节范围，不解析。
- **无法判断的部分**：缺口之后 / 初始状态不明 / 协议错误之后的字节。
